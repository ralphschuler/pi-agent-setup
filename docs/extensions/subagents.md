# Subagents

`extensions/subagents/` registers the custom `subagent` tool.

## Built-in agents

- `scout`
- `planner`
- `worker`
- `reviewer`
- `researcher`

## Capabilities

- List available agents
- Create/delete dynamic custom agents
- Run one bounded specialist task
- Run parallel task arrays with optional concurrency
- Compact live stdout/stderr tails while child agents run
- Write optional outputs for handoffs or reviews
- Opt into `contextMode: "recent"` for a bounded redacted parent-context handoff when a child needs recent parent-session context

## Delegation policy

- Call `subagent action=list` before non-trivial delegation.
- Prefer an existing built-in or custom specialist whose description matches the task.
- Create a narrow custom specialist when no matching specialist exists.
- Dynamic specialist prompts should include a description, tool limits, success criteria, escalation rules, and output contract.
- Keep `contextMode: "fresh"` for isolated research/review by default.
- Use `contextMode: "recent"` only when the child needs parent-session continuity; this sends a bounded redacted parent-context handoff into the child prompt.
- Custom agents with `defaultContext: fork` are treated as `recent` handoff requests; this is not a true session fork.
- Custom agents may declare `readOnly: true` in frontmatter when they are safe to run during `/plan`; missing or false metadata is not read-only.
- The parent agent should keep only the subagent's synthesized summary/result in its working context instead of pasting raw conversation history.
- The parent agent remains responsible for synthesis, verification, final decisions, and user-facing communication.
- Do not use subagents for simple tasks that can be handled directly.

## Good uses

- Read-only reconnaissance
- Implementation planning
- Independent code review
- Parallel research
- Bounded implementation handoffs

## Planning-mode restrictions

During `/plan`, only declared read-only agents may run. Agent creation/deletion and output paths are blocked until approval so child processes cannot bypass repository write protection.

## Context and output limits

`contextMode` controls parent-to-child context:

- `fresh` — default isolated subagent prompt with only the delegated task.
- `recent` — adds a bounded redacted parent-context handoff generated by the parent process. The raw handoff is not returned in subagent result metadata; the parent sees and should rely on the child's synthesized summary.

Live subagent updates are throttled and truncated to recent stdout/stderr tails. Final subagent output is still returned in the tool result and can also be written to an output file for long handoffs. Failed runs preserve redacted stderr diagnostics in the result instead of hiding child-process errors.
